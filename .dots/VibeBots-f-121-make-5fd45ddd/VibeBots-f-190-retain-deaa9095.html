F-190 Retain elevator request identity through uncertain outcomes

Retain one valid UUID for each logical elevator purchase before the network call and persist it across an unknown transport result, malformed success body, retry, and reload. Reuse it only for the same player and an immutable bounded intent fingerprint covering operation, expected depth, and requested placement state. Scope server uniqueness to player plus request id, fail fast when the current client omits or malforms the id, and store enough committed response data to replay the original authoritative success semantics instead of returning a reduced 409. Two concurrent same-id requests must produce one mutation and one logical outcome with no contradictory loser rejection. Client and real-database tests must cover commit plus lost response, reload then retry, changed-intent reuse, cross-player reuse, simultaneous replay, original diff and refunds, and atomic adoption and persistence of world, seed, trip index, gear, consumables, balance, and rail state.
