F-198 Make dot-html reject unknown command-like input

Context: In the tracking worktree, the command dot-html edit --help was intended to inspect edit help. dot-html instead treated edit as a quick-add title and created .dots/VibeBots-edit-f6ca4aeb.html before validating --help. An independent audit repeated the exact live command at 02:21:46 local and created .dots/VibeBots-edit-462e4d44.html. Both resulting Dots have title edit and an empty description. Intentional quoted no-flag quick-add remains supported, but command-like argv with flags must fail closed. Acceptance: parse and validate all argv before any write. Global --help and help for every supported command print help, exit zero, and create no files. Unknown command-like tokens with flags, including edit --help and typoed verbs, exit nonzero with a useful diagnostic and create no file. A recognized command with a missing required argument or invalid option value must also exit nonzero with a useful diagnostic and a byte-identical .dots snapshot. Explicit add remains supported. Intentionally quoted no-flag quick-add remains supported. Parser, validation, and write failures leave no partial file. Run every argument-parser fixture in an isolated temporary repository, never against the live backlog. Tests snapshot .dots before and after global help, supported command help, edit --help, a typo plus flag, add without its required title or an equivalent recognized-command validation failure, explicit add success, quoted quick-add, and an injected write failure. Automation documentation must use explicit add or another supported verb. Known accidental quick-add artifacts VibeBots-edit-f6ca4aeb and VibeBots-edit-462e4d44, stranded provisional VibeBots-f-197-bound-6a08d105, and any further reproduction-created quick-add artifact require separate user approval before deletion and remain outside this slice.
