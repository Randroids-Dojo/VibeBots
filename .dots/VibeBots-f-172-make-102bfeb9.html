F-172 Make post-merge deployment monitoring bounded and SHA-correct

PR #231's post-merge watcher queried repos/<repo>/commits/<sha>/deployments, swallowed the resulting 422, and reported DEPLOY=none until a 25-minute deadline even though the production deployment had already succeeded. Provide a canonical SHA-pinned check using repos/<repo>/deployments?sha=<sha> plus the deployment-status endpoint or equivalent Vercel metadata. Fail visibly on API errors, implement the documented bounded grace exit, distinguish no deployment yet from a bad query, and test success, failure, superseded-main, and unavailable-auth paths without scraping protected production HTML. PR #232 repeated the invalid commits/<sha>/deployments request on exact head 49f2963e, received HTTP 422, and recovered only by reading the Vercel PR comment. The replacement must expose that 422 and must not let a comment fallback mask an invalid SHA query. Concurrent long-lived GraphQL pollers then exhausted the 5000-request GraphQL budget while REST core remained unused, making routine gh pr view checks fail. The replacement must prevent duplicate pollers, use bounded REST checks when sufficient, inspect and back off on the active rate-limit budget, exit at terminal state or deadline, and test low-budget startup, rate-limit responses, restart, and process cleanup. A 2026-07-17 host audit found 17 long-lived zsh polling loops under the shared agent process. At least four still polled completed PR or branch work every 5 to 20 seconds, other loops duplicated repository and transcript watches, and some had run for more than 31 hours. No process was terminated because ownership was not safe to infer. Extend F-172 to register each monitor owner, PID, process start time or unique instance token, command fingerprint, repository, target, cadence, deadline, and output sink; reuse equivalent live monitors; stop or hand off on terminal state, deleted branch, goal completion, interrupt, or expiry; and verify ownership, PID identity, start time or instance token, and command fingerprint before signaling anything. Enforce one active poller per exact repository, target, and purpose, with multiple subscribers sharing that poller, plus bounded API budgets. Test duplicate spawn, parent exit, compaction or handoff, PID reuse, command mismatch, lost registry, uncertain ownership, and cleanup after closed work.
