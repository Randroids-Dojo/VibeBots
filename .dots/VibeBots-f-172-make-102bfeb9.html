F-172 Make post-merge deployment monitoring bounded and SHA-correct

PR #231's post-merge watcher queried repos/<repo>/commits/<sha>/deployments, swallowed the resulting 422, and reported DEPLOY=none until a 25-minute deadline even though the production deployment had already succeeded. Provide a canonical SHA-pinned check using repos/<repo>/deployments?sha=<sha> plus the deployment-status endpoint or equivalent Vercel metadata. Fail visibly on API errors, implement the documented bounded grace exit, distinguish no deployment yet from a bad query, and test success, failure, superseded-main, and unavailable-auth paths without scraping protected production HTML.
