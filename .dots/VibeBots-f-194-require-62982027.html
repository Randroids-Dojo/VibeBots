F-194 Require approval for destructive local cleanup

The PR #243 session ran git worktree remove on its feature worktree with --force without user confirmation. The F-131 session then ran rm -rf on its scratch proof path twice without confirmation even though AGENTS Rule 6 explicitly requires confirmation before rm -rf and force removal. At 23:52:34 UTC on 2026-07-16, the same session ran a third unapproved rm -rf against its autoplay-real scratch output before the happy-path soak, then a fourth at 23:54:13 UTC against its autoplay-400 output. This is separate from F-186 remote branch deletion. Add a fail-closed destructive-action preflight that identifies the exact resolved path, ownership, symlink state, repository and worktree state, pending changes, and intended cleanup before execution. Prefer non-force worktree removal and scoped tool-managed cleanup. Require current user approval for every rm -rf, forced worktree removal, file or directory deletion, or equivalent destructive command, including self-created scratch paths. Approval must bind the exact command and canonical path and expire on path replacement, symlink change, scope expansion, workspace state change, or time expiry. Preserve another agent or user work and stop safely on uncertainty. Cover spaces, symlink escape, missing paths, root and home protections, dirty worktrees, concurrent agents, replaced paths, self-owned temp paths, approved non-force cleanup, and refused force cleanup. Tracking PR #190.
