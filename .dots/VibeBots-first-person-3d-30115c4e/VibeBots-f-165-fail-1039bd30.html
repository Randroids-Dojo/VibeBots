F-165 Fail visibly on incompatible bunker wire state

Add an explicit bunker wire and stored-state compatibility boundary. A stale loaded client must receive a stable refresh-required response instead of dereferencing a missing field into a blank scene. Cover old-client and new-server skew plus unsafe rollback to an old server after null-core writes. Incompatible alpha state must explain the problem and offer confirmed Start fresh recovery. Bound any temporary bridge, then remove the cold-start DROP NOT NULL migration path. Do not carry permanent silent migration chains. Treat a missing blockSeed or an unversioned authored-pocket layout as incompatible stored generation state. Reject it before returning no ore, counting raw dug cells, or subtracting current pocket geometry. The player sees one stable explanation and a confirmed Start fresh bunker action. Cover current valid rows, missing seed, missing or unsupported layout identity, cancellation, confirmation, duplicate confirmation, and reload before and after recovery. Record bounded compatibility outcomes for load and Start fresh with accepted or rejected results and stable current, legacy, unsupported, active-raid, stale-revision, or storage-failure reasons. Hash the player through the existing monitoring boundary. Never retain seeds, coordinates, parts, dug cells, snapshots, request payloads, or human error text. Keep response codes and telemetry reasons aligned, emit no false success, and make telemetry failure nonfatal to gameplay. Require exact layout-version equality so missing, malformed, older, and newer rows all fail fast. Block every ordinary operation on incompatible state, including refunding Reset, repair, and raid start or settlement, not only the four structural edits. Only the explicit no-refund Start fresh path may cross the boundary, and it atomically forfeits any active raid so an old snapshot cannot settle later. Give skin and loot collection an explicit tested policy and return the same stable incompatible code on every blocked stale-client route. Treat the bunker-incompatible response as an authoritative state transition. Every rejected mutation, bank, raid action, or zero-row Start fresh must return an adoptable current bunker view or force a reload before actions resume. A client that believed its bunker was current must expose Start fresh after the server reports legacy state, while a failed reload keeps editing disabled. Cover stale-client mutation, future-version rollback, lost-success retry, and reload failure without retaining a falsely current marker.
