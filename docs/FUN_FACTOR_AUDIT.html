Fun Factor Gap Audit

Backlog generator. Run this audit when docs/GDD_COVERAGE.json is ≥80% done. Re-run after every major system lands. This is the source of the P0 / P1 polish work that prevents the loop from terminating before the product is good. Each gap identified here becomes a Q-NNN open question or an F-NNN followup.

This doc exists because the Flatline failure mode is: every coverage row is done, every test passes, every checkbox is green, but the product is not actually fun. Coverage rows say a system exists. They cannot say the system delivers experience. This audit asks the questions coverage cannot.

How to run an audit

  1. Set today's date as the audit header (<article data-audit-date="YYYY-MM-DD">).
  2. Walk each prompt below. Write a one-sentence answer for each. Be honest. "Yes" answers do not generate work; gaps do.
  3. For each gap, decide: is this a question (Q-NNN) or a followup (F-NNN)?
  4. Add the entry. Reference the audit date in the entry's Context line.
  5. Save the audit. Do not delete previous audits; let the file grow.

Append-only. Earlier audits are preserved.

Prompts

The first session

  • Does the first 90 seconds make the player want to keep playing?
  • What is the first specific moment that surprises a new user (positive or negative)?
  • Where does a new user get stuck or confused?

The core action

  • Does the core action feel good at every skill level (novice, mid, expert)?
  • Is there meaningful skill expression? Can two players visibly perform differently at the same task?
  • Does the core action have texture (light cues, weight, follow-through), or does it feel binary?

Variety

  • Do the variations within the system feel distinct, or do they feel like recolors?
  • If the player picks a "different" option (track / character / mode / layout), do they have a different experience?
  • Is there a surprise still waiting for a player who has played for an hour?

Difficulty arc

  • Where is the difficulty too high (frustration without learning)?
  • Where is the difficulty too low (boredom)?
  • Is there a clear "I want to keep going to get better" pull?

Stickiness

  • What brings a player back the next day?
  • What makes a player tell a friend about this?
  • What is the smallest change that would meaningfully improve retention?

Polish you have been postponing

  • List up to five "we know this needs work" items you have been quietly avoiding. Be specific.
  • For each, name the smallest slice that would meaningfully address it.

Audit 2026-06-11 (mining overhaul complete: re-run of the mining prompts after PRs #16-#21)

Source: VibeReview session docs/reviews/20260610-220517-4C845606/, scripted production and local playtests (screenshots captures/confirm-ore-*.png, captures/juice-*.png, captures/full-*.png). The genre research is at docs/research/mining-mechanics.html.

  • First 90 seconds: Yes. Digging starts instantly with zero instructions, the top rows never wall the first digs, the first ore pops a "+1 cr" float within seconds, and the rock message now points at a shop that actually sells the answer. Baseline gaps F-013/F-014/F-016/F-017 all confirmed fixed in production.
  • Core action texture: Yes, visually: debris bursts in the block's color, shake scales with the event, the miner glides, pickups float, boulders telegraph their fall. The dig is no longer binary. Remaining: audio and crack states (F-019; REQ-018 partial).
  • The core tension is informed: the HUD prices the carry (the bet) and the climb home, and warns when the lamp runs close; the first collapse is now a gamble the player watched themselves take (F-012 confirmed fixed). The wreck reveal then shows what it cost and what was almost in reach ("a part cache sat 5 blocks from where the lamp died"): every failure sells the next trip.
  • Variety: Yes. Seven ore tiers in overlapping bands, five strata with distinct palettes and deepening backgrounds, three rock tiers, two positional hazards, caches, and four gear tracks make trips at different depths play differently. The scripted deep wander met rock walls, hazard blocks, and a cache inside two minutes.
  • Difficulty arc: the gentle top (rock-free and hazard-free rows) ramps into hard gates the shop answers; the superlinear gear ladder keeps "one more trip and I can afford it" alive (observed: 8 trips to the first real upgrade, with the Clay Beds bonus carrying the early wallet). The "I want to keep going" pull is the depth record plus the next band's ore values.
  • Stickiness: persistent deepest-depth record, one-time stratum bonuses, jackpot part caches feeding the bot workshop, and the near-miss reveal. The mining-to-combat economy is the retention spine: dig, cash out, buy parts and gear, fight.
  • Verdict: the mining loop is fun and fully fleshed out per the research's "one more trip" engine; all six baseline gaps (F-012 to F-017) are confirmed fixed in production with zero console errors. New polish backlog: F-019 (audio + multi-hit crack states). Future spec extensions stay listed in the GDD's "not yet" section (smelt combos, collections, surface accrual, server-issued seeds F-011).

Audit 2026-06-11 (mining baseline, before the mining overhaul; focused on /mine)

Source: VibeReview session docs/reviews/20260610-220517-4C845606/, scripted production playtest of /mine (screenshots captures/mine-01..06*.png): two trips, one loot sweep, one push-your-luck descent, cash-out attempt.

  • First 90 seconds: Partly. Digging starts instantly with zero instructions needed, but within 10 seconds the player hits rock whose message ("your pickaxe is not strong enough") advertises an upgrade that does not exist. Gap: F-013.
  • Core action texture: No. Blocks vanish with no crack states, particles, or sound; the miner teleports between cells. The dig is binary. Gap: F-016.
  • The core tension is uninformed: the go-deeper-or-go-home gamble exists in the rules (energy, surface banking, collapse) but the player has no return-cost signal, so the first collapse reads as a cheat, not a lesson. Gap: F-012.
  • Variety: No. One ore (emerald), one obstacle (rock), uniform dirt at every depth; the scripted run saw nothing new between depth 1 and depth 13. Gaps: F-014, F-017.
  • Navigation: retracing a zigzag descent from memory stranded the run at depth 4 with 3 unbanked emeralds; no ladders or escape tools exist. Gap: F-015.
  • Mechanics: solid. Deterministic grid, energy and bank flow correct, cash-out credits the wallet, zero console errors in production.
