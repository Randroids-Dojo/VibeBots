Open Questions

Questions here block or influence implementation.

Critical convention. Every question must include a <dt>Recommended default</dt> entry. The loop ships under that default and leaves the question open for override. Do not block the loop on dev sign-off. Stress-tested values that survive multiple iterations get frozen.

How to add a new question

<section data-q="Q-NNN" data-status="open">
  <h3>Q-NNN: Short title</h3>
  <dl>
    <dt>Context</dt><dd>one or two sentences on why this is a decision point.</dd>
    <dt>Options</dt><dd>
      <ol type="A">
        <li>Option A description.</li>
        <li>Option B description.</li>
        <li>Option C description.</li>
      </ol>
    </dd>
    <dt>Recommended default</dt><dd>B. One sentence on the rationale.</dd>
    <dt>Status</dt><dd>open</dd>
    <dt>Resolution</dt><dd>(filled in once dev confirms or overrides)</dd>
  </dl>
</section>

Keep Q-NNN IDs monotonically increasing. When a question resolves, leave the entry in place and update data-status to resolved plus the Resolution entry. Never delete.

Q-020: Should an all-rock bunker stay nearly unraidable?

Context
The first-person design pass makes depths 1-4 solid claim rock that Clankers can neither path through nor chew. A player who seals the depth-0 plane with parts and never digs gets a fortress whose back is invulnerable rock: the passive version of today's "sealed room wins" outcome, but cheaper relative to the buildable space once 3D raids land.
Options
  1. Accept it: sealed-is-safe is the existing design promise, and digging deeper is opt-in risk for opt-in space.
  2. Make claim rock slowly chewable at high raid tiers.
  3. Scale raid rewards with dug volume so turtling earns proportionally less.
Recommended default
A for this arc. It preserves the current promise exactly and keeps the interim-to-live raid transition balance-neutral; revisit with raid telemetry once live 3D raids ship (F-092).
Status
open (arc will ship under the recommended default)

Q-019: What happens when the player leaves a live first-person raid?

Context
Live first-person raids (design pass 2026-07-13) put the player inside the bunker while Clankers hunt their actual cell. Raids are autonomous once started and cannot pause, but the player can always exit the first-person mode (button, Escape, a closed tab, a dead phone).

  1. Forfeit: the remaining ticks resolve player-absent with Clankers targeting the core; no survival reward; damage stands.

  3. Auto-survive with reduced rewards.
Recommended default
A. It needs no special sim state (a short player trace is the forfeit signal), handles disconnects and abandoned tabs with the same rule, and keeps starting a raid a commitment without imprisoning the player. B fails the phone-call test; C makes abandoning optimal.
Status
open (live-raid slices will ship under the recommended default)

Q-018: Does TV mode's on-screen direction deck square with REQ-024's "no D-pad" rule?

Context
REQ-024 mandates "no page header or D-pad" so the mine reads as a mobile game, and the 0.1.x HUD deliberately deleted the old on-screen D-pad in favor of the thumbstick. Fire TV's Silk browser cannot drag: the remote drives a virtual cursor and Select clicks, so the only remote-native way to move is large stationary click targets, which is exactly an on-screen direction deck. The 2026-07-12 Fire TV controls slice ships that deck for detected TV sessions only.
Options
  1. Scope REQ-024's D-pad ban to touch and fine-pointer sessions; TV mode ships the deck (what shipped).

  3. Make the deck an opt-in setting on every platform.
Recommended default
A. The ban exists so phones read as a game, not to make TVs unplayable; the deck renders only when the session is a TV (UA detection plus a persisted tv query override), so phone and desktop HUDs are untouched. B strands the primary Fire TV input (the remote), and C reintroduces the clutter REQ-024 killed. Shipped under this default; the GDD controls section records the scoping.
Status
open (shipped under the recommended default; needs dev ratification of the REQ-024 scoping)

Q-017: Which purchases should the overall player level actually gate?

Context
REQ-038's last clause makes overall player level "a global progression gate for robot parts, base parts, skins, stamps, consumables, and upgrades." Audit (2026-07-13, F-089): today the level gates raid tiers, the beacon cap, and base-part owned limits; robot parts (/api/shop/buy), consumables, gear upgrades, and bunker skins are purely vibes-priced with no level check. Adding floors invents pacing numbers the GDD does not specify, and retroactively locking items players could buy yesterday is a player-hostile regression.
Options
  1. Design pass assigning level floors across all named catalogs (full clause, biggest pacing shift, risks locking previously buyable items).
  2. Floors only on items added from now on, existing catalogs grandfathered (no regression, clause satisfied gradually).
  3. Amend the GDD to narrow the clause to what already works well (raid tiers, beacon caps, base-part limits) and mark REQ-038 done.
Recommended default
C, with B as the follow-on convention: the shipped level gates are the ones that proved fun (harder raids, more beacons, bigger bunkers), vibes prices already pace the shops, and a blanket retrofit would take purchases away from existing players. If C is approved the GDD clause text changes and F-089 closes; new top-tier catalog entries can still opt into floors per B.
Status
open (needs dev decision: GDD amendments require explicit approval)

Q-013: How literal is "rocks fall a few seconds after the dirt beneath them is mined away"?

Context
The falling-rock request says "a few seconds", but the mine sim is turn-based and deterministic: the server replays the action log to credit cash-outs and there is no wall-clock time in it, and the GDD bars reflex-based hazards (REQ-015, one-thumb friendly). A literal real-time timer would break replay parity and turn the hazard reflex-based.
Options
  1. Count the delay in player actions (FALL_DELAY_ACTIONS = 3), with an escalating tremble tell and a hazard-free top zone. Reads as "a few seconds" while actively mining; standing still is always safe; fully deterministic.
  2. A real wall-clock timer that drops the rock even when idle. Truer to the wording, but requires weaving time into the sim and the server replay, and makes the hazard reflex-based (against REQ-015).
Recommended default
A (shipped). It preserves the determinism contract and the no-reflex rule while delivering the felt hazard. Because rock is common at depth, the gentle-top exemption and the escalating tell are the fairness valves; deep-strata fall density is left for an on-device balance pass (F-022).
Status
open
Resolution
(shipped under default A pending playtest; revisit if falling rock makes deep strata feel collapse-prone or unfair)

Q-009: What is the authority model for a persistent world?

Context
REQ-026: the claim never resets, but cash-out anti-cheat relies on replaying deterministic logs, and a lifetime log grows without bound (multi-hit digging multiplies it).
Options
  1. Store the full lifetime action log and replay it all each cash-out.
  2. Store a sparse world diff per player; each cash-out replays only the trip's log on top of the stored diff, then persists the updated diff (state checkpointing).
  3. Client-authoritative world with server spot checks.
Recommended default
B. Replay cost stays bounded per trip, the diff doubles as the save format for guests (local storage) and the server, and determinism still guarantees an honest client and the server agree given (seed, diff, gear, consumables, trip log).
