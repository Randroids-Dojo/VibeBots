Open Questions

Questions here block or influence implementation.

Critical convention. Every question must include a <dt>Recommended default</dt> entry. The loop ships under that default and leaves the question open for override. Do not block the loop on dev sign-off. Stress-tested values that survive multiple iterations get frozen.

How to add a new question

<section data-q="Q-NNN" data-status="open">
  <h3>Q-NNN: Short title</h3>
  <dl>
    <dt>Context</dt><dd>one or two sentences on why this is a decision point.</dd>
    <dt>Options</dt><dd>
      <ol type="A">
        <li>Option A description.</li>
        <li>Option B description.</li>
        <li>Option C description.</li>
      </ol>
    </dd>
    <dt>Recommended default</dt><dd>B. One sentence on the rationale.</dd>
    <dt>Status</dt><dd>open</dd>
    <dt>Resolution</dt><dd>(filled in once dev confirms or overrides)</dd>
  </dl>
</section>

Keep Q-NNN IDs monotonically increasing. When a question resolves, leave the entry in place and update data-status to resolved plus the Resolution entry. Never delete.

Q-004: Mining presentation

Context
The mining loop is described as an old-school vertical digging game, but the camera, controls, and world format are not finalized.
Options
  1. 2D side-view vertical mine.
  2. 2.5D grid mine with depth layers.
  3. 3D diggable mine.
Recommended default
A. A 2D side-view mine is the clearest prototype path and keeps focus on resource decisions rather than terrain tech.
Status
resolved
Resolution
User override of the default on 2026-06-10: the game is 3D low-poly throughout, and mining keeps 2D vertical-grid logic rendered as low-poly 3D blocks from a side camera. Resource decisions stay readable; the renderer and art style stay shared with workshop and arena. No voxel terrain tech.

Q-003: Online match authority

Context
Autonomous combat between player-built bots needs a trustworthy simulation path for multiplayer results.
Options
  1. Server-authoritative deterministic simulation.
  2. Client simulation with result submission and validation.
  3. Hybrid: client preview, server result.
Recommended default
C. Let the client provide fast previews and keep official match outcomes on a server-controlled path.
Status
resolved
Resolution
User confirmed C on 2026-06-10. The browser previews matches with a local deterministic sim; a Vercel Node function reruns the exact same sim (same rapier WASM build, same seed) for the official result. World snapshot hashes are the verification primitive. Walking skeleton: src/sim/run.ts plus GET /api/sim/verify.

Context

Status
resolved
