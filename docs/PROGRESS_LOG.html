Autonomous Combat Core

Branch
feature/autonomous-combat-core
PR
pending
Changed
combat becomes real: src/sim/combat.ts adds match state for two assembled bots, a drive-at-enemy controller stub (no input surface anywhere, REQ-001), per-part health seeded from a new durability catalog field, contact-force damage via rapier force events (threshold filters rolling/resting contacts), destruction with physical detachment (removeImpulseJoint, debris stays in the arena), and disable conditions (core destroyed, or all mobility parts destroyed). src/sim/assembly.ts now exposes collider and joint-to-parent maps for the damage pipeline.
Verification
dash check, purity check, pnpm typecheck, pnpm lint, pnpm test (26 tests; 6 new combat tests: convergence + contact damage, full-match determinism via snapshot hash plus combat state string, detach, immobilization disable, core-destruction disable), pnpm build, pnpm test:e2e.
Assumptions
damage tuning is measured, not guessed: starter-bot rolling forces peak near 26 N and ram/shove contact near 49 N, so the threshold is 35 N with 0.02 damage per excess newton (sustained shoving grinds parts down over seconds); constants still get a fun-factor pass later. A detached part keeps its own children attached to it (debris clusters); mobility parts riding detached debris do not count toward mobility; both bots disabled in one tick is a draw. Self-review fixes: match-scoped catalog (not the global) drives the mobility rule, axle connectors sit outboard so detachment cannot fire a depenetration damage spike into the core, removed joints are purged from every joint list, and freeMatch releases the WASM event queue.
GDD coverage
created docs/gdd/03-combat-damage-and-disable.html (partial); REQ-001 and REQ-004 flipped to partial; build-log entry on 02 for the durability field.
Followups
none new; steering/behavior parameters and time-limit scoring belong to the next slices (match-end-and-scoring is already in the backlog).
