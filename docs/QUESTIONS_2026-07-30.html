3. The scheduled Full E2E gate has been red for at least six consecutive days

The finding. Every completed scheduled CI run from 2026-07-24 through 2026-07-29 concluded failure. The newest (30442652068, head 4e830d4d) failed 12 of 32 shards.

The triage. Not a regression. Two scheduled runs on the identical commit 41963452 failed different shard sets ({3,5,6,7,8,9,10,20,22} on 07-28 versus {3,6,8,9,11,21} on 07-27). A deterministic regression fails the same shards every time; different sets on the same tree is nondeterminism. Shard 3 resolves to the holodeck pinch-zoom spec, already named in the known-flake list in docs/CI_WORKFLOW.html, and the pattern matches the software-rendering residual that document attributes to F-132.

Why it still matters. A gate that is red every single day carries no signal. Nobody can tell a real Full E2E regression from the standing noise without redoing this shard-set comparison by hand, and Rule 5 step 3 asks every future slice to triage it before picking work. Twelve of thirty-two shards is also well beyond the "a couple of specs" the CI doc describes, so the flake set has likely grown since that text was written.

Recommendation. Make F-132 a real slice rather than background context: either fix or quarantine the flaky specs so the scheduled gate goes green and stays a signal. I did not start it because it is unrelated to the HUD work and could not have its own branch.

The finding. The five fixed hotbar slots are already spoken for by plank left, plank right, dynamite, and recovery, leaving one slot for the tools group (beacon, warp, scrap, abandon).
