Account Sync

Status: partial

Spec

Optional Google sign-in and save sync (REQ-042)

  • VibeBots remains guest-first. A new player can start, mine, build, and save locally without creating an account.
  • The account feature is an optional upgrade path from a guest save to a Google-backed save. The player chooses when to attach the current active save slot.
  • The current active player row is the unit of claim. The first account-sync implementation claims one active save, not all three device slots.
  • After claim, signing in with the same Google account on another machine loads the claimed player row into the active save slot cookie and uses the same server-owned mine, gear, wallet, inventory, bunker, designs, achievements, match records, and notification state.
  • If the Google account already has a claimed save, sign-in never overwrites the current guest save automatically. The player must choose whether to load the cloud save or keep the device save.
  • Provider details stay behind a small account-identity adapter so the account-linking shape can move into VibeKit and be reused by other projects.
  • Use Google sign-in only for identity with openid, email, and profile scopes. Do not request Google Drive, Gmail, Contacts, or other sensitive data for account sync.
  • When the game runs inside a cross-site iframe, sign-in uses a top-level OAuth handoff and a one-time state token so the embedded game's partitioned vb_player cookie is updated in the correct browser storage partition.
  • The recommended first provider is Clerk through Vercel Marketplace because it matches the existing players.clerk_user_id column, has Vercel-managed environment variables, and keeps early usage on a free tier as of the 2026-07-04 research pass.
