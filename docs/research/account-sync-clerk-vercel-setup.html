Clerk and Vercel Setup Checklist for Account Sync

Status: approved Clerk CLI development setup and SDK wiring landed locally. Production Clerk setup remains open; do not promote, upload production settings, or enable paid Clerk features without separate approval.

Goal

Give VibeBots optional Google sign-in without changing guest-first play. A player can keep a local guest save, start sign-in from the mine Account dialog, and claim that active save through the existing one-time handoff routes.

Cost Guard

  1. Use Clerk's Hobby plan for the first account-sync release. Clerk's pricing page still lists Hobby as free, no credit card required, with a 50,000 monthly retained user limit per app, as checked on 2026-07-05.
  2. Do not enable paid Clerk add-ons, organizations, enterprise SSO, custom domains, SMS-heavy auth, or machine-to-machine features for this release.
  3. Use only Google social sign-in from the Account dialog. Do not enable Google One Tap for the first release, because it can prompt sign-in before the player chooses to save to an account.
  4. Before enabling Clerk in production, record the current Clerk plan, retained-user limit, and any dashboard billing warnings in the PR body. If the free-tier terms changed, stop and ask before wiring the SDK.
  5. After launch, review Clerk monthly retained users during release checks. If usage approaches the free-tier limit, log a followup before any paid plan change.

Vercel Marketplace Setup

  1. Install Clerk through the Vercel Marketplace for only the vibe-bots Vercel project.
  2. Confirm Vercel synced NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY and CLERK_SECRET_KEY into the project environments. Clerk's Marketplace guide still says those two variables are auto-synced when the project is connected, as checked on 2026-07-05. The publishable key must start with pk_test_ or pk_live_, and the secret key must start with sk_test_ or sk_live_.
  3. Do not copy Clerk keys from another project. This follows Rule 11's one-backing-store-per-project shape and keeps account identity blast radius isolated.
  4. Pull development env only into a local ignored file when needed: vercel env pull. Never commit pulled values.
  5. Run pnpm ops:check-account-env before setup to confirm the current no-SDK state is safely pending, then run pnpm ops:check-account-env -- --require-ready --google-scopes "openid email profile" after SDK wiring, env sync, and Clerk dashboard scope review. The preflight prints booleans, issue codes, and the required identity scope list only, never Clerk key values; tests cover both the evaluator result and CLI stdout plus stderr.
  6. Keep src/server/account-env-preflight.test.ts passing when changing readiness rules. It compares the CLI preflight with runtime accountProviderStatusFromConfig for ready, missing-key, and wrong-sign-in-url cases.

Clerk Dashboard Setup

  1. Enable Google as the only social connection for the first account-sync release.
  2. Keep Google scopes to identity only: openid, email, and profile. This set is pinned in src/lib/account-google-scopes.ts; do not add Drive, Gmail, Contacts, or other non-identity scopes for account sync.
  3. Leave Google One Tap off for the first release. Clerk's Google social connection guide still documents One Tap as an optional component after Google is added, as checked on 2026-07-05. The only sign-in entrypoint should be the Account dialog button so guest-first play remains quiet until the player asks to save to Google.
  4. Set the app sign-in route to /sign-in. It exists today as a no-SDK optional catch-all placeholder at src/app/sign-in/[[...sign-in]]/page.tsx that redirects to /mine?account=1; the approved Clerk SDK slice should replace that page with Clerk's sign-in-or-up component. The public client env should be NEXT_PUBLIC_CLERK_SIGN_IN_URL=/sign-in.
  5. Do not set NEXT_PUBLIC_CLERK_SIGN_UP_URL for the first release. The Account dialog has one Google entrypoint and Clerk's sign-in-or-up page should keep account creation on the same /sign-in handoff path.
  6. Do not use a hosted Clerk sign-in URL for NEXT_PUBLIC_CLERK_SIGN_IN_URL. The setup preflight and Account dialog both require the local app route so guest-first play and the one-time handoff stay under VibeBots routing.
  7. Set the sign-in fallback redirect to /mine?account=1 with NEXT_PUBLIC_CLERK_SIGN_IN_FALLBACK_REDIRECT_URL=/mine?account=1. Direct visits to the sign-in page without a one-time handoff token must return to the Account dialog.
  8. Set the sign-up fallback redirect to /mine?account=1 with NEXT_PUBLIC_CLERK_SIGN_UP_FALLBACK_REDIRECT_URL=/mine?account=1. Account creation reached from Clerk's sign-in component without a one-time handoff token must return to the Account dialog.
  9. Do not set sign-in or sign-up force redirect URLs for this flow. The Account dialog sends a one-time redirect_url containing accountHandoff, and a force redirect would bypass that handoff.
  10. Leave NEXT_PUBLIC_CLERK_SIGN_IN_FORCE_REDIRECT_URL, NEXT_PUBLIC_CLERK_SIGN_UP_FORCE_REDIRECT_URL, CLERK_SIGN_IN_FORCE_REDIRECT_URL, and CLERK_SIGN_UP_FORCE_REDIRECT_URL unset in Vercel. The setup preflight and runtime provider readiness reject any of these values when present.
  11. Leave NEXT_PUBLIC_CLERK_AFTER_SIGN_IN_URL, NEXT_PUBLIC_CLERK_AFTER_SIGN_UP_URL, CLERK_AFTER_SIGN_IN_URL, and CLERK_AFTER_SIGN_UP_URL unset. Clerk marks these after-redirect variables deprecated for new apps, and VibeBots uses the fallback redirect variables instead.
  12. Keep handoff callback targets on the mine route. The app contract accepts only /mine, /mine?..., and /mine#... return paths before appending accountHandoff.

Until then, keep the non-secret providerStatus.issues checklist accurate so preview and local builds can explain missing setup without exposing keys.

Verification

  • Local with Clerk env unset: guest play works and the Account dialog keeps Google sign-in disabled.
  • Provider status with Clerk env unset after SDK wiring: /api/account/status reports providerReady: false and includes publishable_key_missing, secret_key_missing, public_sign_in_url_missing, public_sign_in_fallback_url_missing, and public_sign_up_fallback_url_missing in providerStatus.issues, without printing secret env values.
  • Ready-gated identity: if a future injected resolver can return a Clerk identity while providerStatus.ready is false, account routes still report signed out and do not attach or mutate cloud-save ownership.
  • Preflight after SDK wiring: run pnpm ops:check-account-env -- --require-ready --google-scopes "openid email profile" with Clerk env loaded from the target environment. The command should fail when keys or redirect settings are missing and should never print key values.
  • Preflight after approved wiring: pnpm ops:check-account-env -- --require-ready --google-scopes "openid email profile" exits 0 only when @clerk/nextjs, the public key has a pk_test_ or pk_live_ prefix, the secret key has an sk_test_ or sk_live_ prefix, NEXT_PUBLIC_CLERK_SIGN_IN_URL=/sign-in, unset NEXT_PUBLIC_CLERK_SIGN_UP_URL, NEXT_PUBLIC_CLERK_SIGN_IN_FALLBACK_REDIRECT_URL=/mine?account=1, NEXT_PUBLIC_CLERK_SIGN_UP_FALLBACK_REDIRECT_URL=/mine?account=1, unset public and server force redirect env vars, unset public and server deprecated after-redirect env vars, and the identity-only Google scope declaration are all present.
  • Local or preview with Clerk env set: clicking Sign in with Google creates a handoff, redirects through Clerk, returns to /mine?accountHandoff=..., consumes the handoff, claims the guest row, and clears the query param.
  • Handoff return route guard: API paths, /sign-in, workshop paths, nested mine paths, and external URLs normalize back to /mine before the callback token is stored or used for Clerk's redirect URL.
  • Sign-in route catch-all: direct visits to /sign-in and nested Clerk sign-in subpaths render Clerk when a public key exists, and fall back to /mine?account=1 when no public key is configured.
  • Fallback redirect: direct sign-in visits without a handoff return to /mine?account=1, open the Account dialog, and clear the query param without a route reload.
  • Sign-up fallback redirect: account creation reached from Clerk without a handoff return to /mine?account=1, open the Account dialog, and clear the query param without a route reload.
  • Conflict case: if the Google account already owns another player row, finish returns conflict and does not overwrite the current guest row.
  • Cross-device case: a fresh browser signed in with the same Google account can load the claimed cloud save into its active save slot.
  • Guest-first quiet start: a fresh guest session does not show Google One Tap, Clerk overlays, or sign-in prompts before the player opens the Account dialog.
  • Cost check: stay on Clerk Hobby until retained-user usage approaches the free-tier limit recorded in the research document.
