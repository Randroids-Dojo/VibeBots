Mine Death Playback Architecture

Audit for F-030. The question was whether the current store-action subscription should stay, be replaced, or migrate toward a different presentation pipeline.

Recommendation

Keep the current store-action subscription as the timing primitive for fatal-fall and falling-rock-crush playback. It is the right bridge between a pure sim that resets the miner immediately and a render loop that must hold the camera on the underground impact cell before the browser paints the reset state.

Migrate incrementally rather than replacing it wholesale. The next cleanup should extract the death-playback derivation and R3F bridge from src/components/mine-canvas.tsx into a small owned helper or hook, but it should preserve the same synchronous subscription behavior and the same canvas diagnostics.

Current Flow

  1. src/sim/mine.ts applies a logged mine action. A terminal result returns collapsed, optional fallFatal or crushed, and lost coordinates while the sim state has already run deterministic recovery back to the surface.
  2. src/state/mine-store.ts commits lastResult, lastAction, and a bumped tick in the same store transaction. Live collapses clear pending bunker edits before the trip is persisted.
  3. src/components/mine-canvas.tsx subscribes to the store in a layout effect and derives a render-only FallPlayback from the committed result and tick. That ref is installed before the next frame can follow the recovered surface miner.
  4. The R3F useFrame loop owns the miner and camera transforms. While playback is active, it samples the playback track instead of the recovered sim position, exposes data-fall-visual-active and data-fall-visual-impact, plays impact SFX at impact time, then clears the visual event after the hold window.
  5. src/components/mine-panel.tsx delays the trip report overlay for fatal falls and crushes, so the player sees the impact before the report takes focus.
  6. Saved terminal trip replays are consumed in src/state/mine-store.ts. The store clears the replayed terminal result after the first recovery so a reload does not loop the same death playback forever.

Options Reviewed

Keep the subscription as-is
Viable for correctness. The subscription is intentionally synchronous and already backed by smoke tests for fatal falls and rock crushes. The weakness is readability: the playback derivation, timeout, frame loop, and diagnostics live inside the largest render file.
Emit explicit render events from the store transaction
Viable later, but not enough by itself. A typed event would clarify ownership, but the canvas would still need a synchronous subscription or equivalent pre-frame bridge because the sim position has already reset. This is best introduced only after more render events share the same path.
Move death playback into a deterministic presentation-state reducer
Not recommended now. Death playback is render timing, not game authority. Putting it in sim-like state would blur the pure replay contract, add persistence questions, and still need a frame-clock adapter for animation.
Use wall-clock timers from the store or panel
Rejected. The death impact belongs to the canvas frame loop where camera, miner, particles, and SFX are coordinated. Store or panel timers would make the first-frame race easier to reintroduce.

Risk Assessment

  • The current subscription is a deliberate race fix, not incidental coupling. Removing it without an equivalent pre-frame bridge can bring back the surface-jump or empty-void frame.
  • The duplicate playback derivation in the subscription and tick layout effect is defensive, but it is also the main maintenance smell. Future agents have to read both paths to prove they install the same event.
  • The sim result already carries the correct authority data. No sim-version or mine-version bump is needed for a presentation-only cleanup.
  • Existing smoke coverage is strong for visible outcomes: fatal fall stays on camera until impact, falling-rock crush starts underground on the first active frame, rendered cells remain populated, the impact flag flips, and the trip report waits.
